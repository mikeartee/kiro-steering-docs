# Semantic Anchors

Steering documents that steer Kiro by *naming* an established method (a semantic anchor) instead of describing it in prose, plus Kiro-specific **semantic contracts** that bundle anchors or define house conventions.

## What's here

This category will hold:

- A document that teaches the semantic-anchors technique — name it, don't describe it; spell out only the delta; and how to tell a real anchor from a dead label.
- A "Semantic Contracts for Kiro" document that publishes reusable, project-scoped contracts mapped onto Kiro's Requirements → Design → Tasks workflow.

## Why a separate category

Semantic anchors are a cross-cutting technique, not a language, framework, or workflow. They apply to how any steering document is written, so they live in their own top-level category rather than under `practices/` or `code-formatting/`.
